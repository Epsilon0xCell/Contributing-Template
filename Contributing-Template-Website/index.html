Contributing-Template

A ready-to-copy contributing guide (CONTRIBUTING.md), generated with generator.contributing.md, for use as the contributing file of another project.

What this is, from me

I keep this repo so I do not have to write a contributing guide from scratch every time. Plainly: this repo's job is to be copied. It is itself a template repo, and its contents are contribution templates for other projects.

The guide in here was generated with generator.contributing.md, and its Attribution section credits contributing-gen. I did not write that template text from nothing, and this page does not claim I did. My work on it was keeping a copy, fixing the broken spots in it, and writing down what an adopter still has to fill in.

If you take one thing from this sheet, take the instruction in the black box below. Everything else on this page is the inventory and the warnings.

The one instruction that mattersCopy CONTRIBUTING.md into your project, then fill in the template slots before you publish it. Do not publish it as-is.

Who this is for

Anyone starting a project who wants a contributing guide in place on day one, and anyone who would rather fill in blanks than stare at an empty file. It fits a project that uses GitHub issues and wants bug reports and enhancement suggestions in a set order.

Blanks left blank on purpose

Four TODO comment blocks stay blank in the template: first code contribution setup, improving the documentation, commit message styleguide details, and joining the project team. Those are fill-in points for the adopting project, not oversights. I left them as TODOs rather than filling them with invented project details.

Warnings I already wrote down in the README
  • No CODE_OF_CONDUCT.md file is included in this template repo. Add one before adopting the guide. The old link to a missing file is fixed, and the empty contact spots now read the project maintainer instead of an invented address.
  • Three documentation links that pointed nowhere now link to README.md in this repo. Point them at your own documentation when you adopt it.
  • The question, bug, and enhancement sections use root-relative /issues and /issues/new links, as the generator wrote them. On GitHub those go to the github.com root, not to your repo. Replace them with your own issue URLs.
